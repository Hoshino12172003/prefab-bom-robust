# V3 Phase 3.2D4 的 11,775 辆根因审计

**主因 `JIT_TIMING_BOTTLENECK`。** D4 对源数据的座椅末段配送弧施加 11 期、75% 的容量损失。低容量区间覆盖 22,000 辆订单的承诺期。第 71 期前最多有 5,775 件座椅能到装配端，剩余三期只有 6,000 辆尚未到承诺期的订单。因此任何政策最多准时交付 11,775 辆，完整整数见证达到该值。恢复日虽另有合计 300 件配送余量，但三天的总装配能力和各自日期的订单均为每天 2,000。按日错配是次级放大因素。源文件提供容量、需求和 JIT 结构，75%×11 期是 D4 压力设计。结果不构成原企业历史上实际发生该座椅中断的证据。

## 1. 最小充分约束及数据链

在 `capacity_at_arc`，`seat-supplier_inv → zp7` 正常能力为 2,100 件/期。原子 336 覆盖 61–71 期，D4 RHS 类 `16106127360`，恢复为突变。原子合法于全部三档事件预算。Γ=2、3 的归档代表额外包含原子 1，但该原子的 61–64 期没有固定电芯收货，所以不改变 RHS。实际生效的只有座椅分支。 [最坏事件表](../artifacts/v3_phase32d4_20261112_191057/gamma_worst_event_comparison.csv)

1. `source.load_tables → compile_network → base.source_base` 读入原 `capacity_c_ijt`、14 期 VIN 需求与实际 BOM。座椅配送、座椅制造和总装提前期为 0。配置逐 VIN 恰好消耗一件其指定座椅。`zp7` 无座椅开盘存量、外采或历史到货，且没有第二条座椅供给弧。整车出库节点 `zp8` 无开盘成车或旁路入流。 [源加载](../src/prefab_v25/source.py#L46) · [V3 编译](../src/prefab_v3/base.py#L72)
2. `run.certified_event` 把原子恢复成实际 profile，与冻结的 `run_matrix.data_for` 映射交叉核对。受扰期的共享配送行右端为 \(\lfloor2100(1-0.75)\rfloor=525\)。同一行合计 Q1A、Q2J、Q4H、Q4P 四个流量，恢复期为 2,100。固定政策模型 `base.add_block` 没有为这些行指定语义名称，原生 Gurobi 行号由构模顺序生成。本次从系数矩阵核出第 61/71/72/74 期对应 `R483/R493/R494/R496`，RHS 为 525/525/2100/2100。 [合法性和映射核对](../artifacts/v3_phase32d4_20261112_191057/run.py#L58) · [容量行](../src/prefab_v3/base.py#L154)
3. 把截至第 71 期的座椅库存等式按 SKU 与日期求和。由库存非负、无替代到货、开盘为零及单位座椅 BOM，累计装配量不超过累计座椅配送 5,775。零期末库存使逐日配送等于装配耗用，但证明这个前缀界只需库存非负，不需额外的 OEM 零库存上界。矩阵样例 Q4H 的第 61/71/72/74 期库存等式为 `R4987/R4997/R4998/R5000`，RHS 为 0，期末库存变量上界为 0。 [流量和库存方程](../src/prefab_v3/base.py#L163) · [库存变量界](../src/prefab_v3/base.py#L192)
4. `zp8` 成车库存等式保证截至 71 期的出库不超过累计装配。前 11 期到期的订单，只有这 5,775 辆最多能按期出库。其余三个到期批次受订单平衡与非负缺口限制，总贡献不超过 \(3\times2000=6000\)。因此
   \[
   Y^{OT}=\sum_g\sum_{t\le d_g}of_{gt}\le
   \underbrace{11\times525}_{\text{到期前缀最多可装配}}
   +\underbrace{(28000-22000)}_{\text{较晚到期订单}}
   =11775.
   \]
   这是单个第 71 期切面已经足够的证明。无须引入电池、发动机、变速箱或座椅细分车型短缺。另一条更强的口径对全窗总完成量也成立，由每日 OEM 零库存和总装容量得到 \(\sum_t\min\{C_t^{seat},2000\}=11775\)。 [订单平衡](../src/prefab_v3/base.py#L183) · [按期目标](../src/prefab_v3/robust.py#L110) · [前缀界实现](../src/prefab_v3/e4_ccg.py#L54)

源码和求解入口未检出显式输入参数 11,775。它出现在结果、证书及断言中。完整追索回放达到 11,775，零政策的 Γ=3 全域证书也达到同值。D4 的保护库存提升证书证明，在预算内任意增加电池缓冲，都可通过注入节点的库存余量保留零政策的完整追索见证。共同合法座椅情景又给每个政策相同上界。事件集合嵌套，所以所有预算可行政策在三档均为 11,775。 [全域证书](../artifacts/v3_phase32d4_20261112_191057/implicit_ccg_exactness_certificate.json) · [全政策集合证书](../artifacts/v3_phase32d4_20261112_191057/policy_flatness_certificate.json)

### 四分支独立上界

对同一固定 \(x=(915,0,0)\)、同一座椅最坏 RHS，仅保留被测分支在总装的 BOM 输入。各分支自己的网络、历史到货、SKU、计划流上限和提前期保留，共用装配、需求与到期规则保留。Battery-only 的 24,997 辆非 BEV 无电池条件。整数求解得到：

| 保留分支 | 完整需求上的最大按期量 | 说明 |
|---|---:|---|
| Seat | **11,775** | 四 SKU 分别匹配，全窗容量与时序同时保留 |
| Battery | 27,363 | 24,997 非 BEV 加 2,366 BEV |
| Engine | 28,000 | 保留原发动机计划流上限 |
| Gear | 28,000 | 保留原变速箱计划流上限 |

这些值针对同一个座椅最坏情景。其他分支在其自身中断情景下仍可造成服务损失。

## 3. 五项最小诊断

Gurobi 13.0.1。单线程，种子 20261110，MIPGap 与 MIPGapAbs 为 0，可行性、最优性和整数容差均为 \(10^{-9}\)。只在进程内构造临时变体，正式数据和模型均未修改。固定场景对照、四个分支和下表数值行均为 Gurobi `OPTIMAL`，目标等于全局界，取整后的变量界及矩阵复核残差为 0。纸面可达量 12,075 已用独立收货最大化验证。

4b 中的原、重排两组共同 SKU 可用上限为 Q1A/Q2J/Q4H/Q4P = 1,062/4,352/5,304/1,357。重排用满 12,075，原日历下实际使用 11,775。这里固定的是可用上限。4c 固定的是已到货的实际件数，两种口径不应混用。座椅生产可以提前，供应商完成品节点可持有库存。原 JIT 下 OEM 可提前收到当期立即用于装配的座椅，不能将座椅留到后一期。成车允许提前装配后持有或迟交；迟交不计 D4 的按期目标。零 lead 只表示同一期可用，模型没有进一步表示日内 JIS 次序。

按 H1–H4 判定，H1 的“原始总量恰为 11,775”被否定，但压力情景确实造成主要的窗口供给损失。28,000 辆与 11,775 辆的差可分为受扰末段总容量较全需求少 15,925 件，以及剩余 300 个末段槽位无法在原日历配对装配。H2 由重排试验支持，原因具体是座椅配送低谷覆盖前 11 个承诺期且后段装配已满。单独取消 OEM 零库存不足以解除这个限制。H3 的型号匹配与 H4 的固定 Seat 排程均不解释最优值。

## 6. 最终回答

- **Q1**　原始 XLSB 的末段座椅名义容量为每天 2,100，11,775 不是原数据的固定 Seat 数量。
- **Q2**　新增压力事件将第 61–71 期座椅末段弧减至每天 525。每车一个合法座椅，无 OEM 开盘或旁路供应。第 71 期前最多 5,775 辆，后面只有 6,000 辆仍可准时。精确见证达到 11,775，故上界紧。
