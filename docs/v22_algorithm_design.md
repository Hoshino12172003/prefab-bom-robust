# V2.2 精确算法与工程边界

完整展开 A0 保留唯一一套 x/y/r/p 和名义运营副本，并为全部允许风险极点增加独立追索。标准 C&CG A1 从零风险场景开始，主问题求得全局下界后固定完整事前方案，对每个极点实际求 Phase-I LP，发现违反场景后追加。

只有所有 SP 都取得最优状态，最大缺口不超过1e-7，且主问题的 ObjVal/ObjBound 绝对差不超过1e-7，才给出鲁棒可行上界和精确状态。任一个 SP 超时或出错即撤销认证，失败候选没有鲁棒 UB。极点数超过256时停止，单模型默认30秒，C&CG最多100轮。

代码复用 V2.1 的物理追索构造、数值流量重放和风险生成接口，V2.1 文件保持冻结。V2.2 的只读 StateView 在模型内部映射初始状态。独立数值审计另外生成组件扣减与 WIP 增加的记账条目，不读取求解器约束来生成期望值，并复算预装配界限及目标费用。

求解器默认关闭强化割。完成无割的回归、三解析例、完整展开/C&CG 回代后，驱动脚本才运行新割测试和有割求解。最后才执行微型 E1—E5 策略比较。每一阶段结果保存 manifest，未到达的阶段没有认证标签。

执行入口为项目根目录的：

~~~powershell
python -m compileall -q src/prefab_v22 tests/test_v22.py examples/run_v22.py
python -m examples.run_v22
~~~

日志由 Gurobi MESSAGE 回调通过 Python UTF-8 写入，兼容当前中文目录。每次运行创建独立时间戳目录，保存输入、每轮主问题、所有 SP、完整流、Ipre/W0post、费用、质量残差、硬件环境、内存和源码哈希。
