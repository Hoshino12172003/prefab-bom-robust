# V3.1 Gate 1 / Gate 2B 规格与实现核对

ZIP 内的最终规格为 `V31_Final_Math_Spec.docx`，映射依据为 `V31_Gate0_Gate2_Audit.xlsx`。参考脚本用于核对建模细节。验收实现以最终规格 §§2–8、10–11、17 和本轮补充指令为准。

| 冲突或证据缺口 | Gate 处理 | 依据与边界 |
| --- | --- | --- |
| 参考脚本把缺少期初库存记录直接解释成零库容 | 82 条原始记录读取期初库存、安全库存界和库存上限。其余九条期初库存为零。四个 OEM Seat 保持 JIT 零上限。其余五个位置分别用零库存及该位置汇集所有合法到达量的有限上界求解。 | `I0` 是已有库存，`K` 是期末库存上界，`b` 是新增保护库存。Gate 1 的 `b=0` 两案相同。参考脚本的零上限只保留为对照，五个位置真实库容仍缺证据。 |
| 原始 `max_inventory=99999` 可能被解释为已测物理库容 | 保留原始模型上限，标为源数据建模值。 | 规格 §8。Gate 2B 结果另标物理库容未验证。 |
| 旧 V3 基模采用加权目标、独立车辆完工及交付变量。参考脚本用一体化按时完工交付 | 复用原始 XLSB loader 和来源工艺工序。独立认证程序使用 `y[g,t]` 表示零时长总装弧上的按时完工并交付；按期目标为所有 `t≤due` 的车辆数量，使用 1,286 个精确组。 | 最终规格 §§5、11。当期完工交付直接使用 `zp7→zp8` 的能力与 BOM，不沿用旧目标。逾期装配不会提升该服务目标，可以省略。 |
| 原始发送行与运营期到货行数量不同 | 保留 117 条历史发送作为来源；逐行按 `departure + lead` 分类。期外到货保留在历史核对表，运营模型仅将 61–74 期到货计入库存。 | 期外到货不得提前到运营期，期内到货不缩放。 |
| 来源节点和厂内库存状态容易混用 | `nodes_inflow` 上的 44 项为合法外部投入，允许就地进入其原始操作，流量受相应弧能力约束。参与缓冲输出的终端状态为工作簿全部 91 键。 | Gate 0 映射与 XLSB 独立恢复逐键相等才允许求解。外部源投料不等于可缓冲的内部库存。 |
| Gate 2A 的结构时间未约束数量 | 独立恢复每个位置的最短完整 BOM 路径，与审计工作簿逐键交叉检查。Gate 2B 用整数材料流及终端库存上限计算数量。三种终端电芯库存按 10:6:4 的完整 kit 比例。 | 规格 §§6–7。初始保护量和保护性在途流均为零。源于原 t=60 的正常库存和历史承诺不转作保护量。 |
| 源表缺少风险前能力和业务占用 | 以每条弧 61–74 期含零值的算术平均作为 `C_nom`，基准 `eta=1`。产品与集团的逐期计划限额无可验证的准备期映射，保留在 Gate 1，未投影到 gross 上界。Gate 2B 使用零 OEM Seat JIT 和五个 T1 位置的技术上界。 | 算术平均是本轮批准的 TRANSFORM 假设。期中保护增量受相应 `K` 限制，t=60 时还给观测到的正常期初库存留出 `I0` 的容量，即 `b≤K−I0`。期中正常库存与资源占用缺少可验证记录。待确认真实库容、准备期供应可获得性和正常业务流，才能作企业实际可形成性的判断。 |
| `H=23` 的边界时间和零时长工序 | 时间轴使用 H 个资源时段，边界为 `0,…,H`。正提前期边从时段起点送出，按 `departure+L` 到货。Seat 零提前期工序及运输可在到货的期末边界顺序完成，使用当期能力；末边界无额外生产周期。 | 规格 §4 及 Gate 2A 的 23 期结构阈值。`H=23` 是基准比较窗口。 |

最终规格、审计表、参考脚本、源工作簿及正式 V3 模型均保留原件。Gate 2B 的量为逐一放大目标位置得到的上界，多个 `Bmax` 不构成同时可实现的缓冲方案。
