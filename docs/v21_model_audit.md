# V2.1 模型差异与审计

实施日期为 2026-11-07。权威定义为用户提供的 `V2.1完整模型.zip` 中《完善后的完整数学模型》。当前分支为 `v2.1-model-certification`。V1 的验收工作区保存为提交 `39810b1`，V2.1 代码位于独立的 `src/prefab_v21/`。

原仓库未有完整 V2 代码。附件中的 `v2_micro_flow_check.py` 与 `v21_structural_checks.py` 已只读核对，前者是单产品局部 SciPy LP，后者是有限极点和割检查。它们缺少第一阶段联合投资、三族场景展开、完整现金/经济成本和精确 C&CG，因此本次以新的全量实现承接权威公式。附件的历史数字未计入本轮测试通过数量。

| 事项 | V2.1 实现与验收 |
|---|---|
| 第一阶段 | 各地点组件预置、二元合同、全窗口累计备用量。所有情景共享同一组决策 |
| 三层风险 | T2、T3、外协风险在运营开始时一次揭示。多池用相同 T3 节点映射，三个连续预算集合取完整极点笛卡尔积 |
| 正常和备用资格 | 分别创建 N 和 NB 发运量，在二者并集上建立输入库存。微型例的备用路径只通向 s1，正常路径只通向 s0 |
| 动态库存 | R、S、I、厂内 Wa、外协 Wo、F 全部逐期非负守恒。负期发运均为零 |
| 两道工序 | 工序1按其 BOM 消耗组件。外协产出的 WIP 必须运输返厂，工序2消耗厂内可用 WIP 和工序2 BOM |
| 交付 | 最终完成、发运和客户收到分别建变量。发运后到达晚于截止期时，强制该发运为零 |
| 三族服务 | 同一个情景的同一追索流联合保证 HV/MV/LV，另以逐族可行而联合缺 2 的反例检验 |
| 财务 | 事前库存购置只计一次。q 包含正常上游常规采购费，正常 T3 发运不另收费。经济目标包含持有费，运营现金约束只含采购、启用、加工和运输 |
| 仓容 | 基础版要求 `enable_storage_capacity=False`。开启会在数据验证时明确拒绝 |

代码未发现与权威公式冲突的定义。上游池之间是互补投入，独立备用替代对应池的输入。数据全部为明示的合成小例，不能凭代码验证真实独立来源资格或制造工艺。

独立残差审计器 `audit.py` 从期初库存出发，以不同的累积流量循环重放所有收货、消耗和转运。它不读取 Gurobi 的约束行来生成预期值，同时复算产能、现金、备用累计量、订单和服务。篡改客户到货变量的反例会被识别。它与求解器共享数据定义，模型正确性证据还包括运输负例、手算最优值及 Gurobi 独立线性目标顶点检查。

Phase-I 是连续 LP。固定事前二元值后，代码将 y 的变量类型改成连续，并用等式锁定其值。仓容关闭时，零新增动作可将强制到货累积入库存，客户保证在途不超过订单，缺口补齐服务，因此具有完全补救。凸值函数的极点最大化保留非饱和和分数顶点，无风险单调性假设。

首次写原始日志时 Gurobi 在中文路径返回 `Unable to write file`，运行被判为 GUROBI_ERROR 并停止。修复为消息回调、Python UTF-8 写日志后重新执行全部 Gate。失败目录保留。
