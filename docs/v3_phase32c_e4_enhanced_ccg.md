# V3 Phase 3.2C E4 实现与有限情景精确验收

**PASS_BTB_CCG_EXACT_AND_EFFECTIVE**

证据范围为 **FINITE_SCENARIO_EXACT_E4_CCG** 和 **STRESS_TEST_ONLY**。沿用历史 t=60 开窗和 t=61–74 的完整整数运营模型。28,000 VIN、28,049 物料、嵌套 BOM、发运和产能、到期日、重排和三类保护库存均沿用冻结基线。

## 实现与证书

E4 保留 Phase 3.2A 的主问题构造和完整整数情景块，使用相同的上下界方向与停止容差。对固定政策按冻结目录顺序求解，使用已精确求得的最小服务作为当前比较值。通过 BOM 物料和时序构造 Pack 到货及座椅 JIT 前缀上界。对于具有相同固定到货和同日同幅座椅容量变化的发动机/变速箱配对，收紧到两场景逐行交集，求完整整数共同见证。仅当见证下界严格高于当前最坏值才排除原场景。上下界相等的场景可以精确认证。其余场景回退到完整 MILP。使用相同字典序规则，逐轮只加入一个严格违反的精确最坏情景。

共同见证优化的全部成本计入 E4。每次共用解保存为压缩整数向量。审计程序独立重建被排除场景的原矩阵、RHS 和变量界，逐条重放该向量，并对照同一政策下 Plain 精确 MILP 的服务量。最终政策均由原完整有限集合的逐情景整数求解重新验证。[数学证明](e4_bound_proof.md) · [剪枝证书](../artifacts/v3_phase32c_20261112_093602/e4_pruning_certificate.csv) · [逐轮交叉核对](../artifacts/v3_phase32c_20261112_093602/e4_iteration_crosscheck.csv)

## 准入测试与公平口径

先完成 74 个固定政策—情景的上下界测试，再运行 C&CG。包括 Phase 3.2B 的 C-only 和 T-only 探针、Phase 3.2P 的 C+T 与 C+T+O，以及实际强运输环境中的 (713,135,6)。前两个探针的原 16 个服务量与 Phase 3.2B 归档核对。

比较 4、8、16、24、32、38 个原有唯一情景。单块起点为原 DE_ENGINE_68，双块再加已验证的 DE_GEAR_61。强运输环境的单块为压力场景，双块为原集合的两条轨迹。Plain 和 E4 每对采用完全相同起点、场景顺序、硬件核心、模型构造、完整追索和最终复核。Direct DE 在新进程中单独构建全部块，并做同口径最终复核。

Gurobi 13.0.1 单线程，种子 20261110，默认 presolve，可行性、最优性、整数容差 \(10^{-9}\)，零绝对和相对 MIPGap。16 及以下每次求解时限 90 秒，较大规模 240 秒。所有计时为实际运行，含构模、求解、矩阵核查及终止复核。每个方法启动新进程，成对方法固定到同一个逻辑核心。机器上运行多个独立测量组，同时最多两项 Direct DE。16、32、38 的单块对照和 Direct DE 均各跑三次，第二次交换 E4 与 Plain 的顺序。计时受并行负载与核心影响，实际运行条件和逐次值均留档。峰值内存为 Windows 进程峰值工作集。

E4 逐轮时长分解为廉价前缀计算、共同见证 MILP、其余单情景 MILP 及调度余量。独立重放证书和交叉审核在计时之外执行，在线生成并保存共同整数见证计入时间。目录只有 38 个唯一情景，64 和 128 不具备同口径规模条件。历史组合风险全集尚待校准与精确分离。[实际计时](../artifacts/v3_phase32c_20261112_093602/e4_runtime_breakdown.csv) · [重复性](../artifacts/v3_phase32c_20261112_093602/e4_repeatability.csv) · [界验证](../artifacts/v3_phase32c_20261112_093602/e4_bound_validation.csv)

## 剪枝来源与验收

58 组运行均达到有限集合精确最优。38 次逐轮对照在相同政策上核对，最坏值与并列集合全部一致。74 个界样本违规数为零。独立重建原情景矩阵验算 52 份不同的情景、政策及向量组合，覆盖 424 项严格剪枝。逐项对照 Plain 完整求解，误剪为零。其中 200 项还满足上下界相等。实际流程先执行严格剪枝分支，故单独走上下界相等分支的次数为零。回归测试覆盖了等值精确认证和可能并列时回退完整 MILP。

分离中 600 项联合风险候选有 424 项被剪枝。电池、发动机、变速箱和座椅的单分支候选均由各自完整 MILP 认证。按成员计，含座椅的 608 项中有 424 项被剪枝。共同座椅日历覆盖同一组 VIN 截止窗口，其他两条支路的容量变化可用同一整数解同时满足，见证服务量严格高于已求最坏值时便可省去两个分别认证。第 61 日的两个并列情景保留个别认证。BES/BGS 配对共用第 66 日的受损电芯固定到货，分别叠加第 61 日发动机或变速箱损失，以及第 61 日相同的座椅损失。相关时间与截止日覆盖逐项留存。[分风险证据](../artifacts/v3_phase32c_20261112_093602/e4_risk_family_analysis.csv)

本轮证据支持在这组有限压力目录上使用 **BOM-Time-Bound Enhanced C&CG（BTB-C&CG）** 名称。基准算法和 Phase 3.2P 政策结论以冻结归档为准。现实风险校准仍待解决。完成后止于 Phase 3.2C。

## 复现

使用同一公开源 ZIP、可运行的 Gurobi 13.0.1、Python、NumPy、psutil、pyxlsb 与 pytest。在独立副本的仓库根目录运行以下 PowerShell 命令，保留冻结归档和原结果。

    $env:PYTHONPATH = 'src'
    $run = 'artifacts/v3_phase32c_20261112_093602'
    python -B "$run/run_e4.py" validate
    if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
    python -B "$run/run_e4.py" all
    if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
    python -B "$run/assemble.py"
    'python -B -m pytest -vv tests/test_v3_phase32c_e4.py' | Set-Content -Encoding UTF8 "$run/pytest.txt"
    python -B -m pytest -vv tests/test_v3_phase32c_e4.py 2>&1 | Out-File -Append -Encoding UTF8 "$run/pytest.txt"
    $testExit = $LASTEXITCODE
    $testExit | Set-Content -Encoding ASCII "$run/pytest_exit_code.txt"
    if ($testExit -ne 0) { exit $testExit }
    python -B "$run/assemble.py"
