## 计时口径与实测瓶颈

端到端时间包含构建 Python/Gurobi 模型及 update、求解器运行、整数解矩阵复核、求解器模型销毁和其余 Python 调度。计时从加载源工作簿之后开始。每次 Gurobi 求解使用相同线程数、种子和数值容差，保留默认 presolve。4/8/16 复跑保留 90 秒和 3 GB 的既有单模型限制。扩展家族的相同对照采用 240 秒、默认内存设置，在独立进程内顺序执行。输入与结果不经过模型文件导入导出，模型序列化耗时为 0。日志写入计入实际端到端耗时。

每次求解的日志还记录 Gurobi presolve、预处理后维数、根 LP 和实际节点。Gurobi 日志未提供独立的纯分支耗时，记录根 LP 和 presolve 之外的求解器剩余时间，其中可能包含启发式、根节点切割和求解收尾。计时汇总将构模和求解互斥拆分，下表的分离和终止复核端到端小计则各自包含其中的构模开销。

## 场景作用与筛选证明

原 4/8/16 的全场景验证均以 DE_ENGINE_61 和 DE_GEAR_61 为并列最坏。两者均含第 61 日 OEM 座椅零提前期配送冲击，发动机或变速箱受扰产出到 OEM 最早为第 63 日。两种起点的最终主问题各含两个块，其中 DE_ENGINE_68 为初始化参考轨迹。因最终块仍可包含非最坏情景，最终块数与精确最坏情景数分别记录。

冻结多 BOM 目录 40 个场景有 38 个有效 RHS。ES 与 DE_ENGINE_61 等价，GS 与 DE_GEAR_61 等价。现有 16 个基准全部保留不同 RHS，两个第 61 日最坏情景在发动机和变速箱容量行上交叉变紧，无法由逐行单调性得出相互支配。对整个目录逐有序对比较，严格支配证据共 85 对。16、24、32 各层内部为 0、26、48 对，分别涉及 0、4、9 个可删除的较弱场景。证明使用容量行包含关系和额外收货的逐期库存吸收映射。候选多 BOM 目录每个非基准风险场景至少有一条 BOM 直接路径在截止日内可达，最低为 B_RECEIPT_1 的 1,266 个 VIN。路径可达给出潜在影响范围，间接容量竞争与库存边界仍需要单独检查。

历史电池集合的 287,443 条轨迹重新核对得到 38,527 个有效 RHS，消除 248,916 条重复轨迹。最大等价类与名义 RHS 类均含 67 条。这个计数是纯 RHS 映射，所对应的组合型分离没有进入本次求解。新增扩展沿用现有 16 个场景，按预定压力机制顺序加入原目录的唯一代表。在扩展中加入原有 E_11 与 S_7 长压力，二者沿用原目录在 Γ=2/4/6 之外的标签。64 个唯一场景超出冻结目录容量。[支配核查](../artifacts/v3_phase32b_20261111_214914/scenario_dominance_audit.csv) · [RHS 等价](../artifacts/v3_phase32b_20261111_214914/rhs_equivalence_audit.csv) · [资源可达](../artifacts/v3_phase32b_20261111_214914/bom_risk_reachability.csv) · [时序核查](../artifacts/v3_phase32b_20261111_214914/bom_time_screening_audit.csv) · [风险模式签名](../artifacts/v3_phase32b_20261111_214914/risk_pattern_signature.csv)

## 增强准入

**E4 的设计获得准入。** 两种固定政策各测 16 个成对情景。使用每辆车恰耗一套座椅、OEM 座椅零库存及 Pack 运输到货前缀构造服务上界。每一对情景再求一个同时满足两者容量的完整整数可行见证，给出共同服务下界。20/32 格上下界相等，28/32 格的共同下界严格优于已求得的第 61 日候选最坏值。每个政策在这 16 个情景上可由 2 次单情景求解及 7 次同组求解完成同样的最坏值和并列认证。这个计数来自逐格证明，基础复跑仍执行了完整枚举与终止复核。当前结论授权范围限于候选设计，有效性依赖实际 BOM、到期日、合格流、库存和相容情景条件。[设计与证明](../artifacts/v3_phase32b_20261111_214914/enhancement_candidate_decision.md) · [安全界](../artifacts/v3_phase32b_20261111_214914/reachability_safe_bounds.csv)
