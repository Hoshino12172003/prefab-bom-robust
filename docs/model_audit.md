# V1 模型正确性审计

2026-11-05 的独立复验、实现缺陷修复和最终证据见 [V1 正确性验收报告](v1_acceptance_report.md)。以下保留首轮审计记录。

## 结论摘要

实现的约束索引、成本口径、决策时序、同场景联合服务和小规模极点认证逻辑相互一致。两个解析算例以及直接展开/C&CG 交叉核验均通过。当前认证只覆盖 V1 连续汇总计划和可完整枚举的小实例，不代表离散生产、动态库存或大规模算法正确性。

## 已确认事项

- 不确定集非空（含零点）、闭且有界；输入校验拒绝 Γ 超过风险节点数。
- 风险只出现在追索 LP 的仿射右端；Phase-I 值函数为凸函数，完整极点足以认证最大缺口。
- 非整数风险预算生成分数极点；整数预算下与二元预算集合的最坏值在测试算例上一致。
- 所有产品族的 σ、流和交付量位于同一 Phase-I LP。T06 的共享资源反例能识别分别求解再拼接的错误。
- (x) 成本只计入第一阶段，(I^0) 不计成本，备用固定费由 (y) 触发，启用费仅由实际 (g) 触发。
- T3 池对所有 T2 的分配作一次总和约束；BOM 对每个组件逐项守恒。
- 直接展开和 C&CG 仅在 Gurobi 返回 `OPTIMAL` 且完整极点认证缺口不超过 (10^{-7}) 时标记精确成功。

## 实现中修正/防止的问题

1. 极点边界：二维 Γ=1.5 的极点数是 5，不是 4；首轮测试暴露并修正了测试期望，生成器未改动。
2. 复现入口：首轮直接运行示例找不到 `src` 包；已让示例显式定位项目内 `src`，第二次运行退出 0。
3. 物理资格：任何正 (b_{ksj}) 若缺少对应 E 或 N 关系立即拒绝；备用弧必须是正常弧子集。
4. 状态防误报：infeasible、unbounded、inf-or-unbounded、time-limit、numeric 和 license error 均有非最优状态，不会映射为 `OPTIMAL` 或精确通过。

## 仍需业务确认的假设

- `b[k,s,j]` 当前解释为组件 (j) 同时需要各个正系数资源池 (k) 的投入。若多个池是同一资源的可替代来源，需增加资源类型/转换或路由变量，不能沿用当前逐池投入式。
- “备用只替代当期同池损失”限制会禁止无风险时使用备用，也禁止备用超过当期损失。删除它后，(g) 会成为一般额外供给，可在名义/轻风险场景扩产，通常降低投资或缺口，但研究问题随之改变。
- V1 的 (q,w) 连续，允许分数产品；这只是汇总计划近似，不认证整数装配可行性。
- 每个场景独立使用 (I^0+x) 是标准两阶段替代场景语义，不表示同一库存跨同时发生的多个场景重复使用。
- 运营资金只计 T2 正常采购和备用启用附加费；若正常 T3 资源本身收费，需新增参数，不能暗中并入现有费用。

## 数值与认证边界

业务量缺口容差为 (10^{-7})，约束残差单独审计。枚举超过 `max_scenarios` 时立即抛出 `ExactEnumerationUnavailable`；目前没有连续双层对偶化等替代精确方法，因此会明确报告未认证。没有证明风险预算必然饱和，也没有假定固定供应商必为最坏节点。
