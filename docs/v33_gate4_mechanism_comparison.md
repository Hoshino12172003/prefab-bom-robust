# V3.3 四机制同实例对照

使用 Γ=1 的 11 个正式场景和正式网格中 229,310.54 USD 的 29-kit 锚点。这一实例在 PR #9 未运行，因此五套已经认证的历史实例均无需重算。四种方法在同一主机上串行、独立起进程，使用相同冻结模型、预算、Gurobi 13.0.1、单线程、Seed 0、零 MIP gap、180 秒单 MILP 上限和 12 GB 软内存上限。方法全部以 11 个原场景重放。计时单独记录迭代 Master、迭代 Oracle、独立重放和全程。

复现时分别用 `--method plain|dominance|bounds|combined` 运行 `experiments/v33_gate4_enhanced/benchmark.py`，每次给不同输出目录。之后执行 `experiments/v33_gate4_enhanced/summarize.py --runs <parent-dir> --out <new-dir>`。统计脚本检查模型输入、场景协议、预算、运行参数和软件环境一致，同时核对三级目标、独立重放残差和原始优化 gap。

速度比是相同实例 Plain 总墙钟除以各方法总墙钟。Oracle 调用降幅相对 Plain，只计迭代中的查询。独立认证所需的全场景回放次数单列。每方法一次运行，适合比较调用数量与该次耗时，可重复性能和置信区间待独立样本复核。

## 排序实验

历史违反仅优先检查已加入 Master 的场景。本轮实现可直接复用这些场景的 Master 见证。因此删除已加入场景后，这条历史规则与按 ID 的固定规则检查同一组待求解场景，二者不存在由此产生的求解先后差异。尚无覆盖多实例的独立训练、验证或测试划分。轻量学习排序的稳定增益和 GNN 的必要性保持 `BLOCKED`。
